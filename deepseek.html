Движение кубика в Unity: WASD + прыжок

Готовый скрипт для мини-игры на Windows с физическим персонажем и идея расширения механики

Содержание

  1. Подготовка сцены
  2. Скрипт PlayerController

Глава 1. Подготовка сцены

Прежде чем писать код, нужно правильно собрать объект в Unity — иначе скрипт не заработает.

  1. Создайте кубик: GameObject → 3D Object → Cube, переименуйте в Player.
  2. Добавьте физику: Add Component → Rigidbody. Массу оставьте по умолчанию (1).
  3. Создайте точку проверки земли: правый клик по Player → Create Empty, назовите GroundCheck. Поставьте её чуть ниже центра кубика (например, Y = -0.5), чтобы она оказалась у нижней грани.
  4. Создайте слой для земли: вверху окна Inspector → Layer → Add Layer... → создайте слой Ground.
  5. Назначьте слой: выделите пол и все препятствия → в Inspector выберите Layer: Ground.
  6. Материал без трения: создайте Physic Material (правый клик в Project → Create → Physic Material), поставьте Dynamic Friction = 0, Static Friction = 0, Bounciness = 0. Перетащите его в поле Material коллайдера кубика. Это нужно, чтобы кубик не прилипал к стенам и не отскакивал.

Глава 2. Скрипт PlayerController

Создайте в папке Scripts файл PlayerController.cs и вставьте следующий код. Затем перетащите скрипт на объект Player.

using UnityEngine;

/// <summary>
/// Управление персонажем-кубиком.
/// WASD — движение по горизонтали, Space — прыжок.
/// Движение построено на Rigidbody, поэтому физика считается в FixedUpdate.
/// </summary>
[RequireComponent(typeof(Rigidbody))] // скрипт сам добавит Rigidbody, если его забыли
public class PlayerController : MonoBehaviour
{
    // ------------------------------------------------------------------
    //  НАСТРОЙКИ (редактируются в инспекторе)
    // ------------------------------------------------------------------

    [Header("Движение")]
    [Tooltip("Скорость перемещения по горизонтали (м/с)")]
    [SerializeField] private float moveSpeed = 7f;

    [Tooltip("Сила прыжка — вертикальная скорость в момент отрыва (м/с)")]
    [SerializeField] private float jumpForce = 7f;

    [Header("Проверка земли")]
    [Tooltip("Пустой объект под кубиком, из которого проверяем землю")]
    [SerializeField] private Transform groundCheck;

    [Tooltip("Радиус сферы проверки — чуть меньше половины кубика")]
    [SerializeField] private float groundRadius = 0.25f;

    [Tooltip("Слои, которые считаются землёй (пол, платформы, препятствия)")]
    [SerializeField] private LayerMask groundLayer;

    // ------------------------------------------------------------------
    //  ВНУТРЕННЕЕ СОСТОЯНИЕ
    // ------------------------------------------------------------------

    private Rigidbody rb;        // ссылка на физическое тело кубика
    private Vector3 moveInput;   // направление ввода с клавиатуры (x, 0, z)
    private bool isGrounded;     // стоит ли кубик сейчас на земле

    // ------------------------------------------------------------------
    //  ЖИЗНЕННЫЙ ЦИКЛ
    // ------------------------------------------------------------------

    private void Awake()
    {
        // Кэшируем Rigidbody — обращаться к нему каждый кадр через GetComponent дорого
        rb = GetComponent<Rigidbody>();

        // Запрещаем физике вращать кубик: иначе он будет кувыркаться при ударах о стены
        rb.freezeRotation = true;
    }

    private void Update()
    {
        // --- 1. Читаем ввод с клавиатуры ---
        // GetAxisRaw возвращает -1, 0 или 1 без плавного сглаживания — для аркады это то, что нужно.
        // Оси "Horizontal"/"Vertical" по умолчанию настроены на A/D и W/S (и на стрелки).
        float h = Input.GetAxisRaw("Horizontal"); // A / D
        float v = Input.GetAxisRaw("Vertical");   // W / S

        // .normalized нужен, чтобы по диагонали скорость не была выше примерно в 1.41 раза
        moveInput = new Vector3(h, 0f, v).normalized;

        // --- 2. Прыжок ---
        // GetKeyDown срабатывает один раз в момент нажатия, а не каждый кадр удержания
        if (Input.GetKeyDown(KeyCode.Space) && isGrounded)
        {
            Jump(jumpForce);
        }
    }

    private void FixedUpdate()
    {
        // --- 3. Проверяем, на земле ли мы ---
        // Рисуем невидимую сферу в точке groundCheck и смотрим,
        // пересекается ли она с коллайдерами слоя groundLayer.
        isGrounded = Physics.CheckSphere(groundCheck.position, groundRadius, groundLayer);

        // --- 4. Двигаем кубик ---
        // Горизонталь берём из ввода, а вертикаль ОСТАВЛЯЕМ прежней —
        // иначе мы бы каждый кадр обнуляли прыжок и падение.
        Vector3 newVelocity = moveInput * moveSpeed;
        newVelocity.y = rb.linearVelocity.y;

        // В Unity 2022 и старше используйте rb.velocity вместо rb.linearVelocity
        rb.linearVelocity = newVelocity;
    }

    // ------------------------------------------------------------------
    //  МЕТОДЫ
    // ------------------------------------------------------------------

    /// <summary>
    /// Задаёт вертикальную скорость напрямую — так высота прыжка всегда одинаковая
    /// и не зависит от массы кубика (в отличие от AddForce).
    /// </summary>
    private void Jump(float force)
    {
        Vector3 velocity = rb.linearVelocity;
        velocity.y = force;
        rb.linearVelocity = velocity;
    }

    /// <summary>
    /// Рисует сферу проверки земли в окне Scene — удобно для отладки,
    /// когда прыжок «не срабатывает» или, наоборот, срабатывает в воздухе.
    /// </summary>
    private void OnDrawGizmosSelected()
    {
        if (groundCheck == null) return;
        Gizmos.color = Color.green;
        Gizmos.DrawWireSphere(groundCheck.position, groundRadius);
    }
}

Глава 3. Настройка в инспекторе

Выделите Player и заполните поля скрипта:

ПолеЗначение
Move Speed7
Jump Force7
Ground Checkперетащите сюда дочерний объект GroundCheck
Ground Radius0.25
Ground Layerвыберите только Ground (галочка на одном слое)

Проверка: нажмите Play, в окне Scene должен появиться зелёный кружок под кубиком. Нажмите WASD и Space.

Если что-то не работает

Прыжок не срабатывает

GroundCheck находится слишком высоко, либо в Ground Layer не выставлены слои пола. Увеличьте Ground Radius для теста.

Кубик липнет к стенам

Не назначен Physic Material без трения (см. Глава 1, п. 6).

Кубик вращается / кувыркается

Проверьте, что Freeze Rotation включён (скрипт делает это сам, но если Rigidbody добавлен вручную — поставьте галочку).

Ошибка GetAxisRaw is not defined

В проекте включён только новый Input System. Зайдите в Edit → Project Settings → Player → Active Input Handling и выберите Both.

Глава 4. Идея усложнения: заряжаемый прыжок

Суть механики. Игрок удерживает Space — кубик постепенно сплющивается (сжимается по вертикали и расплывается по горизонтали), накапливая энергию. Чем дольше держишь, тем выше прыжок при отпускании. Шкала заряда видна прямо на самом персонаже — никакого UI не нужно.

Это идеально подходит именно кубику: визуальная деформация читается мгновенно, а механика добавляет глубину — теперь игрок сам решает, потратить ли время на заряд ради доступа к высокой платформе, или прыгнуть быстро, но низко. Уровни можно строить вокруг этого: узкие проходы (нужен низкий прыжок) и высокие уступы (нужен полный заряд) начинают требовать разного темпа игры.

Доработка скрипта

Добавьте поля:

[Header("Заряжаемый прыжок")]
[SerializeField] private float minJumpForce = 5f;    // прыжок при мгновенном отпускании
[SerializeField] private float maxJumpForce = 14f;   // прыжок при полном заряде
[SerializeField] private float maxChargeTime = 1f;   // сколько секунд копить заряд
[SerializeField] private Transform visual;           // дочерний объект с моделью (для деформации)

private float chargeTime = 0f;     // сколько уже накоплено
private bool isCharging = false;   // идёт ли зарядка прямо сейчас

Замените блок прыжка в Update() на:

// --- Начало зарядки: нажали Space, стоя на земле ---
if (Input.GetKeyDown(KeyCode.Space) && isGrounded)
{
    isCharging = true;
    chargeTime = 0f;
}

// --- Накопление заряда, пока клавиша удерживается ---
if (isCharging)
{
    chargeTime += Time.deltaTime;

    // Отменяем зарядку, если кубик упал с края или его столкнули
    if (!isGrounded)
    {
        CancelCharge();
    }
    else if (Input.GetKey(KeyCode.Space))
    {
        chargeTime = Mathf.Min(chargeTime, maxChargeTime);
        UpdateSquash(chargeTime / maxChargeTime);
    }
    // --- Отпустили Space: прыгаем с накопленной силой ---
    else if (Input.GetKeyUp(KeyCode.Space))
    {
        float t = chargeTime / maxChargeTime;                       // 0..1
        float force = Mathf.Lerp(minJumpForce, maxJumpForce, t);    // плавно между мин и макс
        Jump(force);
        CancelCharge();
    }
}

И добавьте вспомогательные методы:

/// <summary>
/// Деформирует кубик: чем сильнее заряд, тем он ниже и шире.
/// Масштабируем ТОЛЬКО визуальную часть, чтобы не ломать коллайдер.
/// </summary>
private void UpdateSquash(float t)
{
    if (visual == null) return;

    // t = 0 → (1, 1, 1), t = 1 → (1.4, 0.5, 1.4)
    visual.localScale = new Vector3(1f + t * 0.4f, 1f - t * 0.5f, 1f + t * 0.4f);
}

/// <summary>Сбрасывает заряд и возвращает кубику исходную форму.</summary>
private void CancelCharge()
{
    isCharging = false;
    chargeTime = 0f;
    if (visual != null) visual.localScale = Vector3.one;
}

Как настроить visual

Дочерний объект не должен содержать коллайдер. Проще всего: сделайте Player пустым родителем с Rigidbody + BoxCollider, а внутрь положите Cube с MeshRenderer — он и будет visual.

Что это даёт геймплейно

  • Скилловое перемещение — нужно чувствовать тайминг, а не просто жать Space.
  • Читаемость без UI — игрок видит степень заряда на самом персонаже.
  • Дизайн уровней — можно строить «ловушки», где мгновенный прыжок ведёт в тупик, а полный — к секрету.

Глава 5. Другие направления для развития

Если заряжаемый прыжок покажется недостаточным, вот ещё несколько идей, каждая из которых хорошо ложится на куб:

1. Двойной прыжок

Одноразовый прыжок в воздухе. Простая реализация: счётчик jumpsLeft, сбрасывается при касании земли.

2. Рывок (Dash)

Короткий импульс по направлению движения с перезарядкой (например, Shift, кулдаун 1 сек). Даёт скоростное прохождение и позволяет пролетать сквозь узкие щели.

3. Wall Slide + Wall Jump

Прижавшись к стене в воздухе, кубик медленно скользит вниз, а от стены можно оттолкнуться. Требует ещё двух CheckSphere по бокам.

4. Изменение массы

Тяжёлый кубик ломает хрупкие платформы, лёгкий — высоко прыгает и не тонет. Отличная основа для головоломок.

5. Смена гравитации

По нажатию клавиши кубик «падает» вверх. Требует аккуратной работы с осями и вращением камеры, но кардинально меняет восприятие уровня.

Совет

Не добавляйте всё сразу. Возьмите одну механику, доведите её до приятного ощущения и постройте под неё 2–3 уровня. Механика, под которую нет уровней, — это просто кнопка.
